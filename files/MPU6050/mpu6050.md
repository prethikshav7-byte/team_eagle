# MPU6050 Accelerometer/Gyroscope

## Pin Connections (I2C)
- VCC → 3.3V or 5V (check your breakout board — most have an onboard regulator; the bare IC is 3.3V only)
- GND → Ground
- SCL → Arduino A5 (Uno) / I2C clock pin
- SDA → Arduino A4 (Uno) / I2C data pin
- AD0 → GND (sets I2C address to 0x68) or 5V (sets address to 0x69)
- INT → optional GPIO pin for data-ready interrupt signaling

## Wiring Table
| MPU6050 Pin | Connection | What the signal does |
|---|---|---|
| VCC | Arduino 5V or 3.3V | Powers the sensor (onboard regulator handles either) |
| GND | Arduino GND | Common ground reference |
| SCL | Arduino A5 | I2C clock — Arduino drives it |
| SDA | Arduino A4 | I2C data — flows both directions |
| AD0 | GND (or 5V) | Sets I2C address: 0x68 (or 0x69) |
| INT | GPIO, optional | Pulses when new data is ready to read |

## Signal Flow
1. **Power up** — VCC/GND bring the sensor online
2. **Wake** — write `0` to register `0x6B` (PWR_MGMT_1) to exit sleep mode
3. **Read** — Arduino, as I2C master, requests accel/gyro registers over SCL/SDA

## Timing & Protocol Constraints (CRITICAL)
- I2C runs at 100kHz (standard) or 400kHz (fast mode) — set with `Wire.setClock()` if you need faster reads.
- The sensor needs **30-100ms** after power-up to stabilize before the first reliable read.
- Data is read via I2C register access, not custom bit-banged timing (unlike the DHT11).
- The gyroscope drifts over time — re-zero on every power-up rather than hardcoding a fixed offset.

## Protocol Sequence
1. Initialize the I2C bus (`Wire.begin()`)
2. Write `0x00` to the PWR_MGMT_1 register (`0x6B`) to wake the sensor out of sleep mode
3. Read accelerometer registers (`0x3B`–`0x40`) for X/Y/Z acceleration
4. Read gyroscope registers (`0x43`–`0x48`) for X/Y/Z rotation
5. Combine each axis's high and low bytes into a signed 16-bit value
6. Scale the raw value using the sensitivity factor for the configured range (±2g/±4g/±8g/±16g, and similarly for the gyro's °/s range)

## Common Failure Modes
- **Failure:** I2C bus hangs or returns no data.
  **Fix:** Double-check SDA/SCL are on the correct pins, and confirm pull-up resistors are present (most breakout boards include them onboard).
- **Failure:** Sensor is detected but every reading is 0 or constant.
  **Fix:** You forgot to wake it from sleep — write `0` to register `0x6B` (PWR_MGMT_1) on startup.
- **Failure:** I2C address conflict with another device on the bus.
  **Fix:** Tie AD0 to GND (0x68) or 5V (0x69) to select a distinct address.

## Platform-Specific Notes
- **Arduino:** Use the `Wire.h` library directly, or a higher-level library like `MPU6050` or `Adafruit_MPU6050` for register abstraction.
- **ESP-IDF:** Use the `i2c_master` driver APIs; watch for pin conflicts with the default I2C pins.
- **Zephyr:** Use the `sensor` subsystem API with the `mpu6050` devicetree binding; configure sampling rate in devicetree or via `sensor_attr_set()`.
