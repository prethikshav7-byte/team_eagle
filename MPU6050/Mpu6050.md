# MPU6050 Sensor

## Pin Connections
- VCC → 5V (or 3.3V) – module has an onboard LDO to regulate to 3.3V
- GND → Ground
- SCL → I²C clock pin (e.g., A5 on Arduino Uno) – requires a **4.7kΩ pull-up resistor**
- SDA → I²C data pin (e.g., A4 on Arduino Uno) – requires a **4.7kΩ pull-up resistor**
- AD0 → GND (sets address 0x68) or 3.3V (sets address 0x69) – **do not leave floating**
- INT → Digital pin (e.g., D2) – optional but recommended for interrupt‑driven data reading

## I2C Pull‑up Requirements (CRITICAL)
- The SCL and SDA lines **will not function** without pull‑up resistors.
- If your breakout module does not include them, add **4.7kΩ** resistors externally between SCL→VCC and SDA→VCC.
- Without pull‑ups, the I²C scanner will find no device, and all reads will fail.

## Logic Level Compatibility (CRITICAL)
- The MPU6050 internally runs at **3.3V** logic.
- For **5V MCUs (Arduino Uno/Nano):** Most modules include built‑in MOSFET level shifters – check your module. If not, you **must** add a bi‑directional level shifter (e.g., TXS0108) between the MCU and the sensor.
- For **3.3V MCUs (ESP32, Raspberry Pi, STM32):** Direct connection is safe – no level shifter needed.

## Register Read Sequence (Basic)
1. Start I²C transmission to address `0x68` (or `0x69`).
2. Write `0x6B` (PWR_MGMT_1 register) to wake the sensor by writing `0x00`.
3. Write `0x3B` (ACCEL_XOUT_H) to set the start register.
4. Request **14 bytes** from the sensor.
5. Read bytes to extract: 6 bytes for accelerometer (X,Y,Z), 2 bytes for temperature, 6 bytes for gyroscope (X,Y,Z).

## Interrupt Usage (Recommended for Robotics/Drones)
- Connect the **INT** pin to a MCU interrupt‑capable GPIO.
- Enable the `DATA_RDY_EN` bit in the `INT_ENABLE` register (`0x38`).
- The MCU can now enter deep sleep and wake **only** when new motion data is ready – saving CPU cycles and battery power.

## Common Failure Modes
- **Failure:** I²C scanner returns no device at address 0x68/0x69.
  **Fix:** Verify 4.7kΩ pull‑up resistors are present on SCL/SDA. Check that AD0 is tied to GND or 3.3V.
- **Failure:** All readings are zeros or fixed values (e.g., 0, -1).
  **Fix:** The sensor is in sleep mode – write `0x00` to register `0x6B` to wake it. Also ensure you are not reading faster than the sensor can respond.
- **Failure:** Gyroscope values drift significantly over time.
  **Fix:** Calibrate at startup – collect 100 samples and average them as the zero offset, then subtract that offset from live readings.
- **Failure:** Interrupt pin never triggers.
  **Fix:** Enable `DATA_RDY_EN` in `INT_ENABLE` register. Also verify the INT pin is connected to a working interrupt‑capable GPIO on your MCU.

## Platform‑Specific Notes
- **Arduino (Wire library):** Use `Wire.begin()` and `Wire.beginTransmission(0x68)`. For internal pull‑ups on SDA/SCL, you can enable them, but **external 4.7kΩ** resistors are strongly preferred for signal integrity.
- **ESP32 (ESP‑IDF):** Set I²C clock to **100 kHz** initially (`I2C_MASTER_FREQ_HZ = 100000`). ESP32 is 3.3V tolerant, so no level shifter is required.
- **STM32 (HAL):** Configure I²C in `Fast Mode` (400 kHz) and use **DMA** to read the FIFO buffer efficiently for high‑speed data logging.
- **Raspberry Pi (Linux):** Enable I²C via `raspi-config`. Use the `smbus2` library. The Pi runs at 3.3V – **do not** connect to 5V.
